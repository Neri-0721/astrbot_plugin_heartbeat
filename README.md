# 心跳助手（Heartbeat）

为会话里的角色留出周期性的自主活动时间。延续她或他的兴趣、关系和未完的事，可以好奇、分享、接一句玩笑、继续做事，也可以安静过去。默认不布置饭点提醒、催睡或运维任务。

这是一个周期唤醒、逐轮衔接的决策循环。模型在两轮之间不会持续运行；每轮仍使用 AstrBot 的完整主 Agent、当前会话的人格、已启用的工具与 Skills。实际能力取决于会话配置和已安装插件。

## 兼容性与安装

- 版本：3.2.0；声明 AstrBot `>=4.25.1,<5`，已核验的框架版本为 **4.25.1**。后续框架版本仍需验证适配。
- Python 3.12+；Windows 使用 `tzdata` 时区数据，由 `requirements.txt` 声明。
- **所有会话默认关闭**。普通聊天不会自动开启；只有 `enabled_sessions` 名单中的会话才可运行后台 Agent。群聊还需管理员明确允许。
- 从插件仓库安装或更新后，通过 WebUI 重载。在需要的会话发送 `/heartbeat_enable`，再用 `/heartbeat_status` 查看状态；`/heartbeat_disable` 关闭该会话。
- 也可在 WebUI 插件配置中管理 `enabled_sessions`。用 `/heartbeat_status` 取得完整会话 ID，保存配置后重载插件，或由管理员执行 `/heartbeat_reschedule`。新加入且尚无会话信息的 ID 需要收到真实消息后才能运行。

会话按完整的 `平台实例 ID:消息类型:会话 ID` 区分，不支持通配符。同一平台里的不同用户、不同机器人实例、不同 WebUI 聊天窗口分别管理开启状态、任务笔记、手册、到期时间、联系记录和联系额度。后台轮次仍公平串行执行，共享全局每日唤醒预算和调度冷却。

开启、关闭命令直接保存 WebUI 使用的同一份插件配置；重启后依据这份名单恢复，旧 `state.json` 的开启标记和 `last_session.json` 都不构成开启许可。默认 `startup_behavior=auto` 恢复已有信息的已开启会话；保留的 `on_interaction` 选项会等待已开启会话收到真实消息再启动调度。关闭会话保留既有任务和联系记录，重新开启不会重置额度。

手动修改 JSON 文件需要重载插件。配置无法保存时，开启操作不新增许可；关闭操作先在本次运行中生效，并提示保存失败，需要在重启前修复配置。后台事件不能通过这些命令修改名单或全局调度。
- 本版本升级行为和数据迁移见 [CHANGELOG.md](CHANGELOG.md)。完全匹配旧内置默认的全局手册会先备份再迁移；自定义手册保留，升级前请用 `/heartbeat_show` 检查其实际内容。

仓库：[Neri-0721/astrbot_plugin_heartbeat](https://github.com/Neri-0721/astrbot_plugin_heartbeat)。市场是否可安装取决于实际收录状态；仓库中有发布信息不等于已经上架。

## 一轮后台活动如何执行

```mermaid
flowchart TD
    A[每分钟本地巡检：不调用模型] --> B{会话明确开启、到期且有预算?}
    B -->|是| C[公平选择会话；前台忙时让行]
    C --> D[读取手册、任务记录、近期联系与会话历史]
    D --> E[构建完整 Agent；注入人格、Skills、工具]
    E --> F[执行 on_llm_request，再启动 Agent]
    F --> G{角色决定行动}
    G --> H[静默任务或安静结束]
    G --> I[请求联系：发送前复核限制]
    H --> J[保存任务进度与本轮摘要]
    I --> J
```

后台与正常聊天共用 AstrBot 的会话锁，避免两边覆盖历史。执行期间收到真实用户消息时，后台会请求协作停止，并阻止继续发送基于旧状态的联系。已经开始的工具操作可能需要返回后才能停止；每轮另有超时上限。

执行前还会检查 AstrBot 的会话总开关、会话 LLM 开关及插件禁用规则。按配置档和会话规则过滤请求钩子与插件工具；本插件的发送入口在发送时再次核对开启许可和宿主开关。关闭当前会话只影响该会话，不会替其他会话关闭后台。

新版本直接在定时回调中构建并等待完整 Agent，不再排入一个插件无法等待完成的一次性 active job。调用顺序与普通聊天保持一致：构建 → 请求前钩子 → reset → Agent 开始/工具/结束事件。定时任务有独立来源标记，不会被本插件误记为用户聊天。

## 后台活动与主动联系分开控制

“近期聊过”“暂时别找我”“上次问候没有回应”限制主动联系。它们不会阻止 Agent 静默完成已有任务。

主动联系通过受控的 `send_message_to_user` 工具进行，支持原有文本、图片等消息组件，附加两个参数：

- `reason`：这次想联系的缘由；想接着聊、好奇或有来由的玩笑都可以，不必先找一个服务任务。
- `topic`：稳定话题标识，例如 `ongoing-book-talk`、`weekend-plans`，供后续轮次理解联系记录。

发送前重新检查配置时段、近期用户消息、显式免打扰、联系间隔、每天次数、未回应退避与完全相同消息去重。相同话题不再整日封禁，满足间隔后可自然延续。每轮最多成功联系一次，只能联系绑定会话，成功发送后才记账。

默认全天允许活动，不根据钟点推断用户作息。联系至少间隔 1 小时；未回应后依次等待至少 2、4、8、16 小时，用户再次发消息时重置未回应次数。每天 12 次是安全上限，不是应完成的数量。显式免打扰仍有效，静默轮次不会增加未回应次数。费用预算和实际交流限制由程序执行，手册只表达角色如何延续自己的生活与关系。

这些规则是插件消息入口的运行控制，不是对整个宿主环境的隔离。具有独立网络发送能力的第三方工具应遵守心跳提示；插件不能拦截任意 Shell、HTTP 或 MCP 的外部副作用。

## 命令与控制

| 命令 | 作用 |
| --- | --- |
| `/heartbeat` | 帮助 |
| `/heartbeat_status` | 当前会话的后台状态、联系限制、实际规则来源和独立规则路径 |
| `/heartbeat_show` | 显示当前会话实际生效的手册 |
| `/heartbeat_enable` | 明确开启当前会话，写入配置名单，从配置间隔后运行 |
| `/heartbeat_disable` | 关闭当前会话并从配置名单移除；保留历史和任务记录 |
| `/heartbeat_resume` / `/heartbeat_pause` | 开启 / 关闭的兼容别名，修改同一份配置 |
| `/heartbeat_test` | 在已开启会话尝试完整后台轮次；仅略过到期时间，不能绕过开启许可及其他限制 |
| `/heartbeat_quiet 120` | 120 分钟内不主动联系；后台仍可静默做事 |
| `/heartbeat_quiet 0` | 解除显式免打扰，其他联系限制仍有效 |
| `/heartbeat_unschedule` | 暂停全局调度，重启和普通聊天不会自动恢复；需要 AstrBot 管理员权限 |
| `/heartbeat_reschedule` | 重新读取全部配置、恢复全局调度并计算下一轮时间；需要管理员权限 |

聊天 Agent 还可以使用 `heartbeat_set_quiet` 工具，在用户明确要求时设置免打扰；需要当前人格允许该工具。后台轮次不能替用户修改这项设置。

群聊的开启、关闭、免打扰和手动测试需要 AstrBot 管理员权限；普通成员仍可查看当前会话状态与规则。

## 配置

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `enabled_sessions` | `[]` | 明确开启的完整会话 ID 名单；空列表全部关闭，不支持通配符。命令与配置管理同一份名单 |
| `interval_minutes` | `90` | 每会话两轮后台开始时间之间的最小间隔，支持 10—1440 分钟 |
| `startup_behavior` | `auto` | 加载后巡检已明确开启且已有信息的会话；`on_interaction` 等已开启会话收到真实消息后才启动调度 |
| `target_mode` | `all` | 公平轮转已开启的到期会话；`last` 只检查最后收到真实用户消息的已开启会话 |
| `active_hours_start` / `active_hours_end` | `00:00` / `00:00` | 默认全天；如有明确作息约定可设窗口，支持跨午夜 |
| `background_outside_active_hours` | `false` | 时段外是否仍可唤醒做静默任务；开启也不能在时段外主动联系 |
| `check_last_interaction` | `true` | 近期有真实用户消息时暂停主动联系 |
| `interaction_threshold_minutes` | `10` | 上述近期消息时间范围 |
| `max_daily_heartbeats` | `48` | 所有会话共享的每日 Agent 轮次上限 |
| `cooldown_seconds` | `120` | 全局两次后台开始之间的最小间隔 |
| `contact_cooldown_minutes` | `60` | 每会话主动联系的最小间隔 |
| `max_daily_messages` | `12` | 每会话每日成功主动联系的安全上限，不要求发满 |
| `unanswered_backoff_hours` | `2` | 连续未回应的初始等待，逐次翻倍，最多八倍 |
| `agent_timeout_seconds` | `300` | 每轮包括准备阶段的超时上限 |
| `allow_group_sessions` | `false` | 允许群聊；仍需将目标群聊明确加入开启名单 |
| `timezone` | 空 | 继承 AstrBot 时区，再为空则使用系统时区；可填写 IANA 时区名称 |
| `heartbeat_content` | 空 | WebUI 中的全局默认手册；不覆盖磁盘文件 |
| `heartbeat_file_path` | 空 | 显式自定义手册路径，优先于其他来源 |

每分钟巡检不会调用模型。真正开始一轮时才保留额度并设置下次到期时间；执行超时或模型失败的已开始轮次也会计入。缺少模型、请求钩子主动停止或前台占用等准备阶段跳过不计入额度。实际开始还受轮转、时段、前台和预算影响，不提供精确时刻闹钟或补跑积压任务。

## 手册与连续状态

数据存储在 AstrBot 的 `data/plugin_data/astrbot_plugin_heartbeat/` 中：

```text
HEARTBEAT.md                  全局手册；已知旧默认先备份迁移，自定义内容保留
handbook-backups/<SHA256>.md   自动迁移前的原始字节备份
heartbeat.d/<平台实例ID>.md    兼容已有的平台定制手册
heartbeat.sessions/<SHA256>.md 真正独立的会话手册，可自行创建
state.json                    会话记录、预算、全局暂停、成功联系和任务进度；开启许可来自插件配置
last_session.json             旧版恢复文件，迁移后保留原文件
```

规则优先级为：**显式自定义路径 → 会话手册 → 已定制的平台手册 → WebUI 全局内容 → 全局文件**。用 `/heartbeat_status` 获取当前会话文件路径，用 `/heartbeat_show` 确认实际来源。升级不会自动建立平台副本。

旧版自动生成且仍等于全局内容或旧内置模板的副本会按继承处理，原文件不删。已经编辑过的旧副本继续作为覆盖规则，并显示实际来源。如果希望它重新继承，可在确认后自行移走该平台文件。显式文件缺失或损坏会使该轮准备失败，不会偷偷改用另一套规则。

自动迁移仅识别 2.5 的原样内置模板和 3.0/3.1 的原样默认手册（允许 BOM、换行形式及首尾空白差异）。添加过任务、改过措辞的文件不当作默认模板处理。配置里的旧时段和额度也不会被静默改写；升级时应检查它们是否仍符合实际需要。

手册是交给 Agent 理解的自然语言，不是由 Python 执行的规则脚本。示例：

```markdown
最近的交谈、答应的事和你自己在意的东西，都还接着。
想想有什么让你惦记、好奇或想继续的。可以顺着自己的兴趣做点事，也可以什么都不做。
想和对方说话时，从你们正在经历的事情接下去；不必每次都提供帮助、提醒或安慰。
说什么、说多少，顺着你的性格、关系和眼前这件事来，没有固定问候台词。
对方明确想独处、休息或暂时别联系，就尊重这段空间。
```

Agent 可通过 `heartbeat_remember(key, text, status)` 保存少量任务进度，`status` 为 `pending`、`done` 或 `drop`。每会话最多 64 条，每条正文最多 1000 字符。任务笔记和本轮摘要明确标记为 Agent 自述，不能作为独立核实的完成证据。成功联系由实际发送入口记录。

## 验证与开发

```bash
python -m pip install -r requirements.txt ruff==0.15.12
ruff check .
ruff format --check .
python -m unittest discover -v
```

如已有完整 AstrBot 源码和配套 Python，可执行真实构建器/Runner 的离线验证：

```bash
python tools/verify_astrbot.py --source /path/to/AstrBot
```

该脚本使用离线 Provider 和临时数据目录，运行真实 Agent 和工具生命周期，验证静默任务、受控发送、人格和请求钩子衔接；不调用线上模型、不接入真实平台。模型是否会作出合适决定仍需单独进行真实对话验证。详细范围见 [docs/verification.md](docs/verification.md)。
